# Pre-offer engineering boundary

Status: factual scope of the public source milestone; updated 2026-10-03.

- Public source code does not equal a public token offering. This milestone
  publishes source, tests and reproducibility artifacts.
- LOCALNET units have no represented monetary value. Fixture balances and
  public test keys are solely for technical evaluation.
- Mainnet issuance and economics are not finalized. LOCALNET fee=1 and its
  conserved test supply are not final monetary policy.
- No token sale, pricing, trading/exchange integration or monetary distribution
  is authorized by this repository milestone.
- Legal/compliance review must precede any proposed public-value launch.

This document states engineering boundaries. It provides no legal conclusion
and makes no claim of regulatory compliance. The source license remains
[Apache-2.0](../../LICENSE); licensing source code is separate from authorizing
an operated network or public-value activity.

## Explicit approval before any monetary Q1 distribution

Before implementation, promotion or distribution of monetary Q1 units, the human
must approve a concrete package covering all of the following, informed by
qualified advice for the applicable jurisdictions:

| Decision | Required reviewable artifact |
|---|---|
| Issuer/offeror structure | Identified proposed responsible person/entity, authority, roles, contracts and custody/accountability arrangements. No entity is presumed to exist. |
| Jurisdiction | Proposed locations of issuer/offeror, operations, intended recipients and payments; applicable-rule assessment and restrictions. |
| Token economics | Issuance, supply, allocations, founder/treasury treatment, vesting, fees/rewards and governance, with tested accounting and conflicts disclosures. |
| White paper/disclosures | Accurate technical/economic claims, risks, limitations and any required publication/filing process; no reliance on this research README as an offering document. |
| AML/KYC/sanctions controls where required | Applicability assessment, responsible operator, procedures, data protection and tested controls. No claim that every activity requires identical controls. |
| Exchange/listing strategy | Explicit decision whether trading/listing is contemplated at all, and review of any proposed venues, intermediaries, representations and obligations. Approval may be “no listing”; no exchange integration is authorized now. |

Completion of a document is not launch approval or proof of compliance. No token
price, sale, promise of returns, founder allocation, monetary treasury spending,
exchange integration or public-value launch is implemented by this phase.
Any later execution requires explicit approval of the concrete reviewed action.

Development sponsorship and service revenue are separate proposals, subject to
their own contracting, payment and jurisdiction review. They must not be used
to disguise token pre-sales or future token entitlements. See
[early revenue options](../research/Q1_EARLY_REVENUE_OPTIONS.md).
